## Design and sequence

Extend the existing subsystems in place. A replacement architecture would discard
substantial verified work; isolated symptom patches would leave ownership gaps.
Incremental changes to existing boundaries are the chosen approach.

1. P0 audio: reject malformed mono int16 frames before driver writes, contain
   driver ValueError, preserve cancellation and report degraded output in HUD.
2. P0 CodeMode: deterministic natural-language intent classification at the shared
   input boundary; claim ownership before Gemini output, submit the original task
   once. Retain subscription/profile and existing verification/approval. Persist
   model selection atomically, expose it in HUD, accept voice model commands,
   refuse changes while a turn is running. Model aliases avoid invented versions.
3. P0 Spotify: audit native paths, prefer exact saved track identities, measure
   execution time; add authenticated API control where credentials permit, retain
   native control when unavailable. Never treat a title as a track ID.
4. P1 memory/vision/reporting: reuse protected persistent memory, current task
   lifecycle and vision router. Add missing capture/retrieval, input validation,
   bounded failure reporting and focused tests.
5. P2 crew/tools/reconnection/files: bounded retries only for safe operations,
   no replay of mutations; preserve task/input identity and recent context. Wire
   existing safe file-open/reveal controls into historical entries.
6. P3 Netflix/views: explicit idempotent resume after next-episode navigation,
   verify playing; register Telegram view consistently at backend/frontend.
7. Validate focused groups, TypeScript/build, lint, manifests and readiness gates.
   Record evidence below. Physical/device/provider acceptance remains distinct
   from offline tests. Do not claim universal <500ms or zero network outages.
