## 4. Fish TTS speed: where the delay comes from

### 4a. Fish itself (Era's real `FishAudioClient.stream()`, production config)

Config: model `s2.1-pro-free`, `latency=low`, cloned voice `reference_id` set.
Network: DNS 1 ms, TCP RTT p50 52–63 ms to `api.fish.audio` (Cloudflare).
10 runs per cell, warm keep-alive connection, 0 failures in 95 requests.
Time to **first audio byte**, ms:

| latency | 3 words "Yes, of course." | 9 words | 15 words |
|---|---|---|---|
| **low** (production) | p50 **337** / p95 400 | p50 **355** / p95 389 | p50 **331** / p95 556 |
| balanced | 328 / 390 | 336 / 412 | 347 / 388 |
| normal | 463 / 528 | 866 / 1,100 | 931 / 1,126 |

- 15-word vs 3-word on `low` is the same (331 vs 337 ms). Sentence length does not change Fish's first byte.
- The cloned voice costs nothing: model default voice measured 346 / 358 ms (n=5).
- Headers and first PCM byte arrive together, so it is ~280 ms Fish server time plus ~60 ms RTT.
- **Cold connection** (first request after the pooled socket dropped; aiohttp keeps it 15 s): 446 ms and 937 ms in two runs (connect 102–181 ms, slower server first byte).
- A 4 s sentence finishes downloading in ~0.9 s, faster than playback, so the strictly sequential worker in `speech_out.py:270` causes **no** inter-sentence gaps.

### 4b. Era's wait: Gemini text arriving → first Fish request

Probe: Era's session shape (AUDIO + `output_audio_transcription`, same model), 8
typed turns, each transcript chunk timestamped and fed through Era's **real**
`split_sentences()`. 7 usable; 1 returned the whole reply in one transcript chunk with no audio.

| Turn | Gemini first audio | First transcript chunk | First sentence released to Fish | **Era wait** |
|---|---|---|---|---|
| kilobyte #1 | 899 | 899 | 2,489 | 1,590 |
| email #1 | 778 | 778 | 1,699 | 921 |
| greeting #1 ("Hello there!") | 808 | 808 | 1,090 | 282 |
| morning #2 | 752 | 752 | 752 | 0 |
| kilobyte #2 | 503 | 503 | 1,958 | 1,455 |
| email #2 | 874 | 874 | 3,335 | 2,461 |
| greeting #2 ("Hello! One…") | 785 | 785 | 3,403 | 2,618 |
| **median** | **785** | **785** | **1,958** | **1,455** |

So in `fish_audio` mode the first audio the user hears is **≈ 1,958 + 340 ≈ 2.3 s**
after the turn starts, against **≈ 0.79 s** for Gemini's own voice. Fish mode is
**~1.5 s slower at the median and up to ~3 s slower** on these turns.

### 4c. Verdict: it is Era's sentence handling, not Fish and not the network

| Share of the extra ~1.5 s | Cause | Evidence |
|---|---|---|
| **~80%** | **Era waits for a complete sentence** of a transcript that streams at roughly one word per 100 ms | Era wait median 1,455 ms (above) |
| ~20% | Fish server first byte | ~280 ms |
| <5% | Network RTT | ~60 ms |
| occasional | Cold connection after >15 s idle | +0.1–0.6 s |
| occasional, whole turn | DNS failures → fallback (one replayed 0 chunks) | §1 "broken" |

Three concrete mechanisms in `app/era_live/speech_out.py`, each seen in the probe:

1. **`_MIN_SENTENCE_CHARS = 12` swallows short openers.** "Hello!" (6 chars) was merged into the next sentence: released at 3,403 ms instead of ~1,240 ms (**~2.2 s lost** on that turn).
2. **Long first sentences.** At ~1 word/100 ms a 20-word opener costs ~2 s before Fish is even asked ("While I'm unable to directly open your email, I can provide…" → 3,335 ms).
3. **The boundary regex needs whitespace *after* the punctuation** (`_SENTENCE_END`, line 44), so a sentence is released only when the *next* chunk arrives: "account." at 1,570 → released 1,699; "bytes." 1,783 → 1,958 (**+130–175 ms**).

### 4d. Proposed fixes (NOT applied; for session 3, Phase 2a)

| # | Fix | Expected gain | Risk / note |
|---|---|---|---|
| F1 | **Early first chunk**: for the *first* text of each turn, release at the first clause (comma) once ≥ 4 words, or after ~400 ms with no boundary | −1.0 to −2.0 s median | Prosody across the split; first chunk only |
| F2 | Exempt `!` / `?` endings and the turn's first sentence from `_MIN_SENTENCE_CHARS` | up to −2 s on "Hello!" openers | Keep the guard for `.` abbreviations |
| F3 | Release on terminal punctuation at the end of a chunk without waiting for whitespace | −0.13 to −0.18 s | Check "3.5", "e.g." cases |
| F4 | Pre-warm the Fish connection when the user starts speaking (first input-transcript delta) | removes cold +0.1–0.6 s | One cheap request or socket per turn |
| F5 | Retry once immediately on `ClientConnectorDNSError` before the 30 s cooldown; find why the held Gemini buffer was empty (replayed 0 chunks) | removes silent and voice-flip turns | Reliability, not speed |
| F6 | **WebSocket streaming** (`wss://api.fish.audio/v1/tts/live`): feed the transcript into one Fish session per turn and let Fish chunk it | removes the F1–F3 wait structurally | Biggest change: msgpack, barge-in cancel, new tests |

Not recommended: **paid `s2.1-pro`**. Fish server time is already ~280 ms, so the
free tier is not the bottleneck. Also not recommended: **`latency=normal`** (+0.5 s on
9–15 words). `balanced` measured the same as `low`, so there is no reason to change it.
